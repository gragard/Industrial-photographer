# Сайт Сергея Сорокина — инструкция по настройке

Сайт полностью готов и открывается уже сейчас (`index.html`) — просто пока
без реальных фото и без рабочей формы. Ниже — как это включить.

## Быстрый вариант (без админки, руками)

Если пока не хочется возиться с Supabase — можно просто:
1. Положить фото в папку `/images`
2. Открыть `data.js` и в нужном месте прописать `src: "images/имя-файла.jpg"`

Сайт сразу подхватит фото. Админка (следующий раздел) нужна только чтобы
дядя мог добавлять фото **сам**, без твоей помощи и без правки кода.

---

## 1. Настройка админки (Supabase)

Supabase — бесплатный сервис, который даст сайту базу данных и хранилище
для фото, а дяде — нормальный логин с паролем (не хранится в коде сайта).

1. Зарегистрируйся на [supabase.com](https://supabase.com), создай новый проект (Free tier).
2. **Storage** → создать бакет с именем `photos`, отметить его как **Public**.
3. **SQL Editor** → выполнить:

```sql
create table photos (
  id bigint generated by default as identity primary key,
  case_id text,
  url text not null,
  caption text,
  sort_order bigint default 0,
  created_at timestamptz default now()
);

alter table photos enable row level security;

-- читать фото может кто угодно (это нужно, чтобы сайт их показывал)
create policy "public read" on photos
  for select using (true);

-- добавлять и удалять фото может только тот, кто вошёл в аккаунт
create policy "auth insert" on photos
  for insert with check (auth.role() = 'authenticated');

create policy "auth delete" on photos
  for delete using (auth.role() = 'authenticated');
```

4. Аналогично для Storage: **Storage → photos → Policies** — разрешить
   `select` всем, а `insert`/`delete` только `authenticated`.
5. **Authentication → Users → Add user** — создать один аккаунт для дяди
   (его email + пароль, который придумаете вместе). Это и есть логин для `/admin.html`.
6. **Settings → API** — скопировать `Project URL` и `anon public key`,
   вставить в `config.js`:

```js
supabase: {
  url: "https://xxxxx.supabase.co",
  anonKey: "eyJhbGciOi..."
}
```

Готово — `/admin.html` заработает, дядя сможет входить своим email/паролем
и загружать фото, они сразу появятся на сайте.

> Важно: `anonKey` — это публичный ключ, ему и положено быть в коде сайта,
> это нормально и безопасно. А вот пароль от аккаунта дяди нигде в коде
> не хранится — Supabase проверяет его на своей стороне.

## 2. Настройка формы заявки (Telegram)

1. В Telegram написать **@BotFather** → команда `/newbot` → следовать инструкциям, в конце получишь **токен бота**.
2. Написать этому боту любое сообщение (просто "привет").
3. Открыть в браузере:
   `https://api.telegram.org/bot<ТВОЙ_ТОКЕН>/getUpdates`
   и найти в ответе `"chat":{"id": ЧИСЛО ...}` — это **chat_id**.
4. Вписать оба значения в `config.js`:

```js
telegram: {
  botToken: "123456:AAExxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx",
  chatId: "123456789"
}
```

После этого заявки с формы на сайте будут падать дяде прямо в Telegram.

> Токен бота будет виден в исходном коде сайта — это осознанный компромисс
> для простого MVP: максимум, что может сделать посторонний, узнав токен —
> написать этому боту лишние сообщения. Если захочется закрыть и это —
> нужен маленький сервер-прослойка (можно обсудить отдельно, когда понадобится).

## 3. Публикация на GitHub Pages

Так же, как был опубликован старый сайт:
1. Залить все файлы в тот же репозиторий (`index.html`, `admin.html`, `styles.css`, `script.js`, `admin.js`, `data.js`, `config.js`, папка `images`).
2. GitHub Pages подхватит `index.html` автоматически.

---

## Структура файлов

- `index.html` — главная страница
- `admin.html` — панель для загрузки фото (для дяди)
- `styles.css` — все стили
- `script.js` — логика главной страницы
- `admin.js` — логика админки
- `data.js` — тексты кейсов и запасные (fallback) фото, если Supabase не настроен
- `config.js` — ключи Supabase и Telegram (сюда вписываешь свои значения)
- `images/` — папка для фото, если решишь не использовать Supabase
